Спецификация требований для проекта "Умная парковка" УраганDev
1 Введение
1.1 Назначение
Этот документ содержит спецификацию требований к программному обеспечению (ПО) для системы «Умная авто парковка», версия 1.0. Система представляет собой веб-приложение для автоматического мониторинга занятости парковочных мест. Документ предназначен для команды разработчиков, тестировщиков, менеджеров проекта и заинтересованных сторон, участвующих в создании и внедрении продукта.
1.2 Соглашения принятые в документах
В данном документе приняты следующие типографские соглашения:
●      Основной шрифт: Times New Roman, кегль 14 pt.
●      Требования оформляются в виде ненумерованного списка с маркерами в виде черных кружков.
●      Заголовки всех уровней выделяются полужирным начертанием.
1.3 Границы проекта
Продукт «Умная авто парковка» предназначен для автоматизации процесса поиска свободных парковочных мест. Система использует потоковое видео с камер видеонаблюдения и заранее обученную нейросетевую модель для детекции транспортных средств и определения статуса каждого парковочного места. Результат в реальном времени отображается в веб-приложении, где пользователь видит:
●      Общее количество свободных мест.
●      Схематичную карту парковки с визуальным обозначением свободных и занятых мест.
Цель продукта — сократить время поиска парковки для водителей и повысить эффективность использования парковочного пространства.

2 Общее описание
2.1 Общий взгляд на продукт
«Умная авто парковка» — это новое, самостоятельное веб-приложение, которое интегрируется в существующую инфраструктуру парковки через камеры видеонаблюдения. Продукт получает видеопоток, обрабатывает его с помощью алгоритмов компьютерного зрения и предоставляет агрегированные данные о занятости через пользовательский веб-интерфейс.
Контекстная диаграмма: Система взаимодействует с серверами камер видеонаблюдения для получения видео и предоставляет данные конечным пользователям через веб-браузер.

2.2 Классы и характеристики пользователей
●      Водитель (Конечный пользователь): Использует веб-приложение для быстрого поиска свободного парковочного места. Не требует специальных технических знаний. Заинтересован в простоте, наглядности интерфейса и актуальности данных о свободных местах.
●      Управляющий парковкой: Отвечает за эксплуатацию конкретной парковки или сети парковок. Имеет доступ к расширенной статистике использования (загрузка по времени суток, среднее время занятости места, доходность). Может настраивать зоны детекции для камер своей парковки и управлять отображением схемы. Технически подкован, работает с системой регулярно.
●      Администратор сервиса/проекта (Супер Администратор): Обладает полным контролем над всей системой. Ключевые функции: управление учетными записями всех пользователей, настройка прав доступа, добавление и конфигурация новых парковок в системе, обновление программного обеспечения, мониторинг общей работоспособности системы и серверов. Обладает высшими техническими привилегиями.
2.3 Операционная среда
1. Модель ИИ: Для детекции автомобилей должна быть использована самописная нейросетевая модель, при этом модель может быть кастомизирована под специфические условия целевой парковки.
2. Технологический стек:
○      Серверная часть должна быть реализована на Node.js в связке с PostgreSQL для обеспечения работы веб-интерфейса и хранения данных
○      Для работы нейросетевой модели используется Python 3.8+ с фреймворком PyTorch/TensorFlow
1. Совместимость: Система должна быть совместима с RTSP (Real Time Streaming Protocol) потоками с камер видеонаблюдения наиболее распространенных производителей (Hikvision, Dahua, Axis).
2.4 Ограничение дизайна и реализации
1. Визуальные требования:
○      Соблюдение фирменного стиля проекта в цветовой палитре и типографике
○      Использование интуитивно понятных иконок и визуальных элементов
○      Обеспечение достаточного цветового контраста для accessibility.
1. Функциональные элементы интерфейса:
○      Обязательное отображение схемы парковки с цветовой индикацией свободных/занятых мест
○      Реализация легенды для объяснения цветовых обозначений
○      Отображение счетчика свободных мест в реальном времени
○      Адаптивная верстка для мобильных устройств (минимальная ширина 320px)
1. Навигационные ограничения:
○      Единообразная навигация для всех типов пользователей
○      Максимальная глубина вложенности меню - 2 уровня
○      Быстрый доступ к основной функции (просмотр состояния парковки) с любой страницы
1. Производительность интерфейса:
○      Время загрузки основной страницы не более 3 секунд
○      Плавное обновление состояния парковки без перезагрузки страницы
○      Оптимизация графических элементов для быстрой загрузки
1. Дизайн-система:
○      Использование Material-UI или аналогичной проверенной дизайн-системы
○      Единые компоненты для кнопок, форм и элементов управления
○      Консистентность интерфейса across different devices and browsers
2.5 Предложения и зависимости
Предположения:
Качество и доступность входных данных:
○      Предполагается, что камеры видеонаблюдения обеспечивают стабильный RTSP-поток достаточного для корректной работы нейросетевой модели разрешения и качества.
○      Освещение на парковке в темное время суток является достаточным для детекции автомобилей, либо парковка оснащена системой искусственного освещения.
○      Углы обзора камер остаются неизменными после первоначальной настройки зон детекции.
Данные для модели:
○      Для первоначального обучения и последующих дообучений самописной модели будет предоставлен репрезентативный и размеченный датасет изображений с целевых камер.
Инфраструктура и эксплуатация:
○      Предполагается наличие и стабильная работа серверной инфраструктуры (включая GPU для инференса модели) с бесперебойным интернет-соединением.
○      Аппаратная часть камер и серверов будет поддерживаться в исправном состоянии.
Зависимости:
Внешнее программное обеспечение и библиотеки:
○      Критическая зависимость: Работа системы зависит от стабильности и производительности выбранных версий Node.js, PostgreSQL, Python и библиотек для нейросети (PyTorch/TensorFlow, OpenCV, YOLO).
○      Зависимость от Open Source: Проект использует ряд сторонних открытых библиотек и фреймворков (например, Express.js, React, Leaflet.js), их обновления или обнаруженные уязвимости могут потребовать изменений в коде.
Аппаратные зависимости:
○      Система зависит от наличия GPU с поддержкой CUDA для обеспечения требуемой скорости обработки видео.
○      Зависит от исправности и совместимости камер видеонаблюдения и их поддержки протокола RTSP.
Операционные зависимости:
○      Работа системы в режиме, близком к реальному времени, критически зависит от пропускной способности канала между камерами и сервером обработки.
○      Доступность веб-приложения для конечных пользователей зависит от надежности хостинг-провайдера или облачной платформы.
Проектные зависимости:
○      Сроки и качество разработки напрямую зависят от своевременной поставки размеченных данных для обучения и валидации нейросетевой модели.
3.    Функции системы
3.1. Распознование свободных мест на парковке
3.1.1. Приоритет:Высокий
Описание: Базовая функция системы которая заключается в обученной нейросети для поиска свободных мест на парковках на основании предоставленного видеопотока с камеры
3.1.2. Функциональные требования:
●      Система должна определять свободные места основываясь на данных которые предоставил видеопоток
●      Система должна работать с кадрами, которые анализируются раз в 15 секунд
●      Система должна предоставлять результат в виде массива где:
1 - место свободно, 0 - место занято
3.2. Просмотр списка доступных парковок
3.2.1. Приоритет: Высокий
Описание: Возможность просмотреть перечень всех парковок, подключенных к системе, с отображением их названия и местоположения.
3.2.2. Функциональные требования:
●      Система должна предоставлять публичную веб-страницу со списком всех доступных парковок.
●      Посетитель может выбрать интересующую его парковку кликом по конкретной из списка
●      Система должна предоставить возможность поиска в виде текстового поля куда можно написать часть названия парковки, отображаемый список должен быть отфильтрован исходя из введенного в поле
●      Для каждой парковки в списке должно отображаться ее название и адрес (или краткое описание местоположения).


3.3. Просмотр детальной информации о парковке
3.3.1. Приоритет: Высокий
Описание: Возможность для Посетителя перейти на страницу конкретной парковки и увидеть детализированную информацию о количестве мест.
3.3.2. Функциональные требования:
●       Система должна предоставлять возможность перехода на страницу парковки из общего списка.
●       На странице парковки система должна отображать: 1. Название парковки 2. Общее количество парковочных мест 3. Текущее количество свободных мест 4. Схему парковки
3.4. Получение информации о свободных местах в реальном времени
3.4.1. Приоритет: Высокий
Описание: Возможность видеть актуальное количество свободных мест, которое автоматически обновляется на основе данных с камер и системы распознавания.
3.4.2. Функциональные требования:
●      Система должна предоставлять схематическое изображение парковки, где: красным отмечены занятые места, а зеленым свободные
●      Система должна автоматически обновлять данные о количестве свободных мест без необходимости обновления страницы пользователем.
●      Система должна отображать время последнего обновления информации о свободных местах.
3.5. Авторизация в системе
3.5.1. Приоритет: Высокий
Описание: Возможность войти в защищенную часть системы для управления конкретной парковкой.
3.5.2. Функциональные требования:
●      Система должна предоставлять интерфейс для ввода логина и пароля Администратора. Интерфейс имеет вид расположенных по центру экрана полей: Имя пользователя, Пароль; и кнопки "Войти"
●      Система должна предоставлять возможность скрывать или раскрывать введеный пароль с помощью кнопки в правом углу поля ввода пароля
●      Система должна отреагировать на неверно введеные данные текстовым сообщение между кнопкой "Войти" и полем ввода пароля
●      Система должна проверять учетные данные и предоставлять доступ только к данным той парковки, которая закреплена за Администратором.
3.6. Просмотр статистики парковки
3.6.1. Приоритет: Средний
Описание: Возможность просматривать детальную информацию о своей парковке в административном интерфейсе.
3.6.2. Функциональные требования:
●      Система должна отображать текущее состояние парковки: общее количество мест, количество свободных и занятых мест.
●      Система должна отображать статус подключения к камере и работу системы распознавания.
3.7. Управление разметкой парковки
3.7.1. Приоритет: Средний
Описание: Возможность изменять общее количество парковочных мест на своей парковке.
3.7.2. Функциональные требования:
●      Система должна предоставлять интерфейс для изменения общего количества мест на парковке.
●      Система должна применять новое значение общего количества мест для корректного расчета свободных мест.
3.8. Управление учетными записями администраторов
3.8.1. Приоритет: Высокий
Описание: Возможность создавать, редактировать и удалять учетные записи администраторов парковок для администратора проекта, а также назначать им привязку к конкретным парковкам.
3.8.2. Функциональные требования:
●      Система должна предоставлять интерфейс для создания новых учетных записей администраторов с указанием логина, пароля и привязки к парковке.
●      Система должна предоставлять возможность изменения данных существующих администраторов и переназначения их на другие парковки.
3.9. Управление парковками
3.9.1. Приоритет: Высокий
Описание: Возможность добавлять новые парковки в систему для администратора проекта, редактировать их параметры и удалять существующие.
3.9.2. Функциональные требования:
●      Система должна предоставлять интерфейс для добавления новых парковок с указанием названия, адреса и привязки к источнику видеоданных.
●      Система должна позволять редактировать основные параметры существующих парковок и настраивать подключение к камерам.
3.10.                Мониторинг состояния системы
3.10.1.                     Приоритет: Средний
Описание: Возможность отслеживать работоспособность всех компонентов системы в реальном времени.
3.10.2.                     Функциональные требования:
●      Система должна предоставлять дашборд с отображением статуса работы всех камер и модуля распознавания.
●      Система должна отображать историю сбоев и статистику работы системы за выбранный период.
3.11.                Отчёты формируемые на основе статистики использования парковок
3.11.1.                     Приоритет: Средний
Описание: Возможность для управляющего парковкой формировать отчёт по конкретной парковке в форматах: за период по дням и проценту занятых парковочных мест, средняя занятость парковки по часам в разные дни недели
3.11.2.                     Функциональные требования:
●      Система должна предоставлять кнопки для формирования отчетов на странице администратора для конкретной парковки
●      Система должна вывести всплывающий диалог с формой для отчёта. В форме содержатся поля: 1. Дата начала отчёта 2. Дата конца отчёта 3. Выбор типа отчёта: "% занятых мест", "средняя занятость"
●      Система должна отобразить отчёт на отдельной странице панели администратора парковки
3.12.                Глобальная конфигурация системы
3.12.1.                     Приоритет: Средний
Описание: Возможность настраивать общесистемные параметры и политики работы.
3.12.2.                     Функциональные требования:
●      Система должна предоставлять доступ к настройкам алгоритмов распознавания и параметров интеграции с камерами.
●      Система должна позволять настраивать системные параметры, такие как интервалы обновления данных и пороги оповещений.
5. Требования к внешним интерфейсам
 5.1. Пользовательские интерфейсы
Возможность просмотреть парковки с разных устройств, например, посетители используют телефон для просмотра, администраторы - компьютер. Система должна отображать адаптированную веб-страницу в соответствии с устройством пользователя или администратора. На веб-странице для мобильных устройств должны преобладать крупные элементы интерфейса для удобства пользования за рулем, все необходимое будет отображаться на главном экране, остальные функции будут размещены в сайдбаре.
5.2. Интерфейсы ПО
Система  взаимодействует с несколькими внешними и внутренними компонентами для предоставления функционала мониторинга парковочных мест в реальном времени и уведомления пользователей. Ключевые интерфейсы включают: 1. камера для получения видеопотока. 2. Интерфейс обработки искусственным интеллектом для анализа кадров и детектирования свободных мест. 3. интерфейс с мобильным приложением пользователя, который отображает статус парковки. 4. интерфейс с базой данных для хранения данных истории и конфигурации.
6. Атрибуты качества
6.1. Удобство пользования
Система должна быть интуитивно понятной, а также удобной, что крайне важно для Посетителей. Удобство должно достигаться крупными элементами интерфейса, такими как большое поле для видео, кнопки и т.д. На главном экране приложения должны быть наиболее важные функции.
6.2. Производительность
Система распознавания должна распознавать 4 кадра в минуту.
6.3. Безопасность
На сервере не должны сохраняться никакие изображения
